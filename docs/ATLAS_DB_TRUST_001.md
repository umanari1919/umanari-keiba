1. **保存・可用性**：既存DBの稼働状態、物理バックアップの整合性、復元手順、原本の所在を別途確認。DBクラスタの自動起動、修復、初期化、データ移動は禁止。
2. **DB構造**：明示した同意と安全な読取専用接続が可能になったときに限り、`tools/atlas_db_trust_001.py --inspect` の単一カタログSELECTで `mykeibadb` の重要テーブル・列・宣言制約・推定行数を確認。既定動作は**完全オフライン**。SQLを自動再試行しない。
3. **粒度と整合**：実データの検査は次の別Mission。競走単位(`race_code`)・出走馬単位(`race_code, ketto_toroku_bango`)・調教単位（日付・時刻・所属など）の一意性、JRA/NARの日時・コース・開催ID、未収録期間、重複、孤立参照、結果と出走の対応を時間区間別にチェック。
4. **遅延と未来情報**：取得日時とレース発走時刻を区別し、結果データが予測特徴量へ混入しないことを確認。
5. **Canonical研究用公開**：JRA/NARの正式`Source Adapter Contract`とソース利用権限が検証され、ステージング→正規化→差分照合→検査済み不変版が揃ってから許可。元DBを研究用に直接改造しない。

## 取り込み簡素化の仕様（次段階・まだ実装しない）

操作を手動SQLから切り離し、**投入元をフォルダーに置くだけ**の仕組みにする。

- Source IDと権利・出典・対象期間を元に処理可否を決める。
- 更新はファイルハッシュ・取得バージョン・処理済み台帳で冪等化し、同じ入力の再投入では増殖させない。
- 入力は`INBOX → 検査 → STAGING → (必要なら隔離) → 独立したCanonical候補`の順。既存生DBの上書きはしない。
- 失敗時は不変の原本・理由別レポートを保持して再試行可能にする。部分成功をPASSと表示しない。
- 権利未確認データ、確定していない出走表、欠損結果は自動昇格しない。
- 最終的な日本語画面は「最終取込日時・増分件数・重複数・欠損数・隔離数・次の更新予定」だけでも運用できるようにする。
